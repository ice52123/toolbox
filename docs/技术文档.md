## 1. 项目速览

### 1.1 它是什么

一个面向校园的聚合前端站（**校园集 / CampusToolBox**），主要内容：

1. **工具箱**：22 个纯前端小工具（JSON 格式化、时间戳、Base64、哈希、进制、正则、JWT、图片压缩/转换/水印、PDF 合并/拆分、密码、UUID、颜色、单位换算、万年历、汇率、天气、快递、油价、公交）。
2. **校园社区**：P3 校园社区（板块 + 帖子列表 / 详情 / 发帖 / 评论 / 点赞 / 收藏 / 搜索）。
3. **闲置市场**：qiankun 微前端子应用（`/m/idle`），自身是独立 Vue 应用，含发布 / 列表 / 详情 / 订单。
4. **社交与交易**：好友、私聊、订单闭环（下单 → 发货 → 收货 → 评价）、钱包、收货地址。
5. **多租户校园**：顶部「校园切换器」+ `/api/schools`，内容按校区隔离。

另有两个 Express 后端（MySQL 版 / MongoDB 版）作为双后端实验，**接口契约一致、同一套前端可切换**：已落地用户 / 工具 / 上传 / 学校 / 首页 / 社区 / 帖子 / 个人 / 闲置 / 订单 / 消息 / 聊天 / 好友等模块（MySQL 版约 60+、Mongo 版约 45+ 条接口，详见 `docs/API-清单.md`）。qiankun 还注册了 `campus-forum`(P3) / `message-center`(P5) 两个占位子应用。

## 2. 设计系统（主题 / 样式 / 断点是怎么做的）

这块是全站的地基，几乎所有页面都在吃它。三份文件各管一层，改动前先看清谁管什么。

### 2.1 三层样式文件

| 文件 | 角色 | 关键约束 |
|---|---|---|
| `styles/tokens.less` | **编译期** Less 常量（不是 CSS 变量），如断点 `@bp-sm:900px`、圆角、控件高度、动效时长、`z-index` | 不产出任何 CSS；只放"与主题无关"的常量 |
| `styles/variables.less` | **运行时** CSS 变量 `var(--tb-*)` 的唯一来源（`:root` + `@media(max-width:900px)` + `html.dark{}`） | 会跟着主题变的**只有这里** |
| `styles/mixins.less` | 复用片段（不产出 CSS）：`.m-sm()` `.m-md()` `.m-xs()` `.m-phone()` 断点 mixin、`.flex-center()`、`.card-surface()`、`.grad-brand()`、`.btn-base()` 等 | `composes` **不能**写进 mixin（CSS Modules 硬性要求） |
| `styles/utilities.less` | **全局**原子类（非 module）：`.tb-page` `.tb-card` `.tb-h` `.tb-row` `.tb-btn` `.tb-chip` `.tb-tool` `.tb-cols-3`… | 首屏/列表这类通用外观都在这 |
| `styles/ui.module.less` | **CSS Modules 共享原子类**，各页通过 `composes: tb-card from global` 复用 | 用 `composes` 只能挂在顶层规则、只能挂在"没有自身声明"的类上 |
| `styles/index.less` | 全局样式唯一入口（main.js 只引它），串起上面几个 + `base.less` | `@import` 顺序不能动（变量先于使用） |
| `styles/base.less` | 重置 + body 基调 + `html{scroll-behavior:smooth}` + 细滚动条 + 锚点 `scroll-margin-top:90px` | — |

**记忆法写在 tokens.less 文件头**：会跟着主题变的写 `var(--tb-xxx)`，不会变的才写 `@` 常量。谁要是把写死的十六进制塞进组件样式，深色模式下必翻车（早期 👤 emoji 头像就是这么脏的，见 §6.4）。

### 2.2 断点（编译期 Less 变量）

| mixin | 变量 | 值 | 主要用途 |
|---|---|---|---|
| `.m-sm()` | `@bp-sm` | **900px** | 紧凑头部 + 底部 tab 分界、一行三块压竖排、工具网格收窄 |
| `.m-md()` | `@bp-md` | **1000px** | `.tb-cols-3` 压成 1 列 |
| `.m-xs()` | `@bp-xs` | **620px** | 表单 label 改上下堆叠（SmsFields） |
| `.m-phone()` | `@bp-phone` | **430px** | iPhone SE 档：工具页隐藏末尾分类标签 |
| — | `@bp-xl` | 1200px | 仅定义，暂无业务使用 |

另有若干页面**裸写**媒体查询（没走 mixin）：`variables.less` 的 900px、`utilities.less` 的 1000/900px、`Auth.vue` 的 1000/520px、`Community.vue` 的 900/480px、`Message.vue` 的 900/420px。**改断点要两处一起改**（`AppLayout` 的移动端判定是 `window.innerWidth <= 900`，和 `@bp-sm` 手工对齐，没有共享变量）。

### 2.3 主题机制：亮/暗 × 主色（两个维度）

**状态在 `stores/theme.js`（Pinia）**

- 读 `localStorage`：`tb_dark`（`'1'`/`'0'`）、`tb_accent`（默认 `violet`）。
- actions：`toggle()` / `setDark(v)` / `setAccent(key)` / `apply()`。前三个都是「改 state → 写 localStorage → 调 apply()」。
- `setAccent(key)` 先校验 `accentPresets.some(...)`，非法 key 直接 return。

**`apply()` 干的事**（关键，别只看一半）：

1. `document.documentElement.classList.toggle('dark', dark)`；
2. 写 `--tb-primary` / `--tb-secondary` / `--tb-primary-soft(-2)` / `--tb-primary-ring`；
3. **同时写 Element Plus 的主色** `--el-color-primary` 与 `light-3/5/7/8/9`（用 `mix('#ffffff', primary, t)` 向白混）、`dark-2`（`mix(primary,'#000',0.2)`）；
4. 派生 `--tb-gradient-text`（120deg 三段渐变）和 `--tb-aurora`。

> 为什么必须同时写 `--el-color-*`：只换主色、按钮还是紫的，看着像没生效。

**兜底/覆盖**：`variables.less` 里 `html.dark{}` 只覆写变量（不重复写媒体查询）；`index.less` 另有 `html.dark` 覆写 Element 主色与 `--tb-bg` 径向渐变；`Auth.vue` 用 `:global(html.dark) .glass{}` 处理组件作用域内暗色。

**三类「表面色」（改新控件前先看这两行）**

| 变量 | 亮 / 暗 | 管什么 |
|---|---|---|
| `--tb-card` | `.72` 白 / `rgba(23,27,46,.55)` | 卡片底 |
| `--tb-surface` | `.72` 白 / `.06` 白 | 输入框、头像等**比卡片更高一层**的表面 |
| `--tb-pill` | `.7` 白 / `.09` 白 | 分类胶囊、筛选 pill 这类**实心小按钮**的底（2026-10-04 新增，起因见 §2.5） |

三者都是「自己带一小块底」的控件，区别只在层次和对比强度：`--tb-pill` 因为要压住 `--tb-sub` 的浅色文字，暗色档只给 `.09`（浅底会吞字）。

**主色预设在 `config/theme.js`**：5 套 —— `violet 星夜紫 #7c3aed/#ec4899`、`ocean 深海蓝 #2563eb/#06b6d4`、`mint 青竹绿 #0d9488/#84cc16`、`sunset 落日橙 #ea580c/#f59e0b`、`rose 玫瑰红 #e11d48/#f472b6`。配套工具函数：`hexToRgb`（支持 3 位缩写）、`toHex`（钳制 0-255）、`mix(c1,c2,t)`、`rgba(hex,a)`。

**两种主题切换入口**（都在 Me 页）：顶部胶囊分段（浅/深）+ 5 个圆形主色板（选中态 `box-shadow: 0 0 0 3px card, 0 0 0 5px primary`）。

### 2.4 布局高度变量（微前端要用）

`--tb-header-h: 92px`、`--tb-tabbar-h: 0px`（900px 以下改 96px / 56px）、`--tb-max-w: 1240px`、工具卡 `--tb-tool-h: 118px`（900px 以下 100px）。

这两个高度变量是 `MicroAppHost` 算子应用容器高度的依据：`min-height: calc(100vh - var(--tb-header-h) - var(--tb-tabbar-h) - 28px)`。

### 2.5 两处踩过的样式坑（改动时留意）

- **CSS Modules 下同名类只能算一个类**：`.ava` 与 `.avaBig` 必须写在同一条选择器里，分开写后写的会把前面整条盖掉（PostDetail.vue）。
- **断点内跨选择器改类必须写顶层**：写在 `.themeRow{}` 里的 `.m-md({ .chipLb{...} })` 会被拼成 `.themeRow .chipLb`，选择器语义就错了（Me.vue 里有注释留证）。
- **半透明白底不能写死**：分类 pill 原来写 `background: rgba(255,255,255,0.7)`，深色模式下它盖在深色页上仍是浅底，而正文色 `--tb-sub` 在 `html.dark` 里被覆写成浅色 `#a9a6c0` → **浅字压浅底，字几乎看不见**。修法不是给 `.cat` 单独加 `html.dark` 覆写，而是把这套「实心小按钮的底」提成主题变量 `--tb-pill`（`:root .7` / `html.dark .09`），跟 `--tb-card`、`--tb-surface` 归到同一类表面色。**凡是「自己带一小块底」的控件，加之前先问一句：这个底在深色下是变亮还是变暗？**
- **判断「深色下看不清」的三步**：① 底是不是写死的浅色/白色；② 字是不是 `var(--tb-sub)`（深色下会变亮，浅底上就翻车）；③ 选中态有没有跟着一起变（选中态建议用 `--tb-primary` + `#fff` 保住高对比）。
- **子应用要自己引 EP 的深色变量表**：`element-plus/dist/index.css` **不含** `theme-chalk/dark/css-vars.css`，漏了它，主站虽然已经挂上 `html.dark`，子应用内的输入框 / 下拉 / 标签仍是浅色一套，深色页面上糊成一片。`main.js` 里必须单独 `import 'element-plus/theme-chalk/dark/css-vars.css'`（独立运行时 `html.dark` 不存在，无副作用）。子应用自己的文字色同理走主题变量 `--im-fg` / `--im-fg-soft` / `--im-pill`（`:root` 给亮色、`html.dark` 覆写暗色），**不要写死十六进制**——这一条对 `idle-market` 尤其要紧，它以前一层变量都没有，`styles.css` 里只有一句写死的 `.im{color:#221f33}`。

## 3. 全局骨架

### 3.1 `main.js`（应用装配，唯一插件注册入口）

顺序：Vue 3.5 `createApp` → `use(pinia)` → `use(router)` → `use(ElementPlus)` → **遍历 `@element-plus/icons-vue` 全部组件 `app.component(key, comp)` 全局注册**（所以模板里能写 `<component :is="'Shop'" />` 这种字符串图标）→ 装 `ElMessage` → 引 `element-plus/theme-chalk/dark/css-vars.css` + `styles/index.less`。

**全站错误兜底**（两条互补）：

```js
app.config.errorHandler = (err, _i, info) => {
  console.error('[ CampusHub ] 运行时错误：', info, err);
  try { ElMessage.error('页面出错了，已安全降级'); } catch {}
};
```

`try/catch` 是为了 `ElMessage` 自己炸了不再二次抛。它管不到被 `onErrorCaptured` 拦下的错误，那个由 `ErrorBoundary.vue` 管。

已知代价：Element Plus 全量引入，包体偏大（构建时有 chunk > 500kB 警告）。

### 3.2 `App.vue`

只有一个 `<router-view />`，刻意不做布局。因为 `/auth` 是整屏独立、不套主站外壳，其余页面套 `AppLayout`，两种外壳都挂在这一层出口之下。

### 3.3 路由表（`router/index.js`）

- `createWebHistory`，**全页面 `() => import(...)` 懒加载**（单页加载失败只坏这一页并触发 `router.onError`，不像静态 import 在入口整站崩成白屏）。
- `/auth` 在 `AppLayout` **之外**（routes 顶层），所以登录页永远没有顶导。
- `/` 挂 `AppLayout`，children 覆盖：`''/home`、`tool/:id`、`tools`、`m/:app` 与 `m/:app/:rest(.*)*`（两者都指向 `MicroAppHost` 且 `props:true`，微应用深层路由不落到 404）、`idle` 重定向 `/m/idle`、`idle/:rest(.*)*`，以及子应用内部路由桥接 `list` / `publish` / `detail/:id`（qiankun 下子应用与主站共享 history，子应用 `push('/list')` 会把主站 URL 变成 `/list`，这三条必须指回闲置宿主，否则一整片 404）。
- 业务路由：`community` / `message` / `orders` / `me` / `about` / `notice` 与 `notice/:id`（同一组件两态）/ `roadmap` / `chat`（`redirect:'/chat/c1'`）与 `chat/:id` / `post/:id` / `user/:name`（昵称带中文，跳转处 `encodeURIComponent`）/ `order/:id` / `order/:id/review` / `forum`（ComingSoon 占位，带 props）。
- 兜底 `:pathMatch(.*)*` → `NotFound`。
- `router.onError` 目前**只 `console.error`，没给用户任何提示**（可补）。**全项目无 `beforeEach` 导航守卫**，权限判定散在各页面 `v-if`。

### 3.4 `layout/AppLayout.vue`（全站外壳）

结构：`el-container` 包 顶部导航 + `main`（内含 `ErrorBoundary > router-view`）+ 页脚 + 回到顶部 FAB + 移动端底部 tab。

关键实现：

- **移动端判定靠 JS 而非纯 CSS**：`isMobile = ref(false)`，`syncMobile(){ isMobile.value = window.innerWidth <= 900 }`，`onMounted` 挂 `resize`/`scroll`（`scroll` 用 `{passive:true}`），`onBeforeUnmount` 摘掉。桌面端渲染 nav / 搜索框 / 主题开关 / 用户下拉；移动端顶部只留品牌，个人信息走底部 tab「我的」，搜索走工具页内框。
- **筛选状态绑定 store**，不逐层传 prop：`const keyword = computed({ get: () => ui.keyword, set: v => ui.setKeyword(v) })`（注释记录历史 bug：早先把 prop 拷进 ref 只认一次，停在 `/tools` 时改顶部框没反应）。

- `onMounted` 里主动 `theme.apply()`，保证直接进子路由也把主题变量写上（因为 `apply` 只在点开关时调）。
- 下拉**标题本身不跳转**（点标题只展开菜单），`onNavCommand(key)` 先遍历 `modules` 找子项：工具分类只有 `key` 没 `path` → 只想 `ui.setCat(key)` 且不在 `/tools` 就 `push('/tools')`；`action==='logout'` → `user.logout()` + 提示 + 回首页；其余 `push(item.path)`。

- 未读红点 `ui.unread>99 ? '99+' : n`，桌面挂「我的」标题右侧、底部 tab 挂图标右上角（带 2px 白描边）。

### 5.2 `views/MicroAppHost.vue`（宿主，三层失败处理）

- `app = computed(() => getMicroApp(props.app))`（props 来自路由 `props:true`）。
- **entryUrl 同源策略**：`location.hostname` 是 `localhost`/`127.0.0.1` 时走 `app.devUrl`（4200，同源无跨域），否则 `new URL(app.entry, location.origin).href`（公网走 `/idle-app/`）。这是绕开 qiankun 跨域拉取这类最难排查错误的关键。
- **统一登录透传**：`childProps()` 返回 `{ token, username, userId, path: subPath, onLogout }`；`subPath` 把 `route.params.rest` 数组 `join('/')` 整理成 `/list` 之类（默认 `/list`），子应用靠它落到正确页面——否则子应用解析到 `/m/idle` 这种它不认识的路径，只剩顶部一条栏。
- **三层失败处理**：① `mountPromise.catch()` 记 errMsg + 转 fallback；② **4s 内容器 `textContent` 为空** → fallback 挂 iframe；③ iframe `load` 事件里**只有 `probeOk` 为真才撤掉失败卡**（连接被拒绝时浏览器同样会给 iframe 触发一次 load，不加这个条件会把真正的失败提示抹掉只剩空白）。
- **`probeDevServer()` 真的 fetch 一次**（`AbortController` 2.5s 超时、`cache:'no-store'`）——不再拿「N 秒内没 load」当判定（vite 首次编译子应用动辄十几秒，会把"正在加载"误报成"连接被拒绝"）。`watchFrame` 延迟 2s 后才探测更新 errMsg。
- iframe 用 `v-if` 控制挂载、`v-show` 控制可见（这样它不管多慢都能触发 load）；`frameKey` 换 key 强制重拉；`onBeforeUnmount` 里 `unmount()` + 清 timer；`watch(() => props.app)` 先卸载再挂载（防泄漏/重复挂载报错）。
- **诊断 UI**：连不上时一张 `.down` 卡，文案分两种——`frameOk` 为真时说「子应用还在加载，这多半只是首次编译慢…会自动恢复」；探不通时直接把端口、要执行的 `npm run dev`（idle-market 目录 / 项目根 `npm run dev:all`）和控制台报错原文写在页面上，配「重新加载」「在新标签打开」两个按钮。

### 5.3 idle-market 子应用本身（独立 Vue 应用）

- 技术栈：Vue 3.4 + Vite 5 + Element Plus 2.7（全量）+ Pinia（**挂了实例但没建 store**）+ vue-router 4（`createWebHistory`）+ `vite-plugin-qiankun`，`type: module`，dev 端口 4200，`@`→`./src`。
- **qiankun 生命周期**：`renderWithQiankun({ mount, bootstrap, update, unmount })`；`mount(props)` → `render(props)`；挂载点 `container.querySelector('#app') || container`（兜底直接用 container，避免 `mount(null)` 静默失败只剩顶栏）；`unmount()` 里 `app.unmount(); app = null`。
- **子路由补齐**：`const to = props.path || '/list'`，`router.isReady().then(() => { if (currentRoute.path !== to) router.replace(to) })`。
- **base 是两套**：`vite.config.js` 的 `base: '/idle-app/'`（决定产物资源路径前缀，不设的话资源是 `/assets/...` 绝对路径会指到主站域名去取 → 404）；`src/router/index.js` 的 `base = qk ? '/m/idle' : '/'`（决定子应用 history 前缀，主站挂在 `/m/idle` 而非 `/idle`，写错会导致子应用 push 时改写主站 URL）。
- **独立运行形态**：`document.body.classList.add('idle-standalone')`，渐变背景只在 `body.idle-standalone` 生效；`App.vue` 顶栏 `v-if="!embedded"` 内嵌时收掉；「返回主站」用 `window.location.href = VITE_MAIN_APP_URL || http://localhost:5173`（整页刷新，非 SPA 路由）。
- **列表页顶栏不带品牌块**：`views/List.vue` 的 `.sub-nav` 只有「返回主站」+ 右侧筛选区（分类 / 搜索 / 我发布的标签 / 发布闲置）。内嵌时人在闲置市场里，再摆一个「🛍️ 闲置市场 + 逛一逛（→ `/list`）」等于指回自己、点了原地打转，所以品牌那块整个去掉；详情页和发布页要回列表，它们各自有「返回列表」「逛一逛」按钮，不缺这个入口。
- **两种运行形态的判定**：`main.js` 和 `router/index.js` 都双读兜底——插件导出的 `qiankunWindow.__POWERED_BY_QIANKUN__`、真实 `window.__POWERED_BY_QIANKUN__`（router 里还有 `window.proxy.__POWERED_BY_QIANKUN__`），取 truthy 那个。

详见 §7。

### 6.1 首页 `Home.vue`（`/`）

**做什么**：Hero（品牌语 + 两个 CTA）+ 竖向滚动公告条 + 三格快捷入口 + 「最新闲置 / 校园热帖」双列信息流 + 工具推荐位（默认 6 个，「更多 N 个 ›」）。

**技术**：Element Plus（`el-button/el-input/el-link/el-tag/el-empty`）、`tools`+`categories` 配置、`mockData` 的 `stats/notices/latestGoods/hotPosts`、`useUiStore`。

**关键实现**：

- 筛选状态**直接读 ui store**（顶部搜索框 / 顶部「工具」下拉 / 工具页内框 / 首页推荐位读同一份），不用再透传 prop。`filtered` = 分类 + 关键词（关键词比对 `name` 与 `desc`，都 `toLowerCase`）。

- 图标底色**按序号循环 9 段渐变**（`palette(i) = palettes[i % 9]`），保证同一批卡不会颜色撞车。
- 公告竖向滚动：`.n-view{height:22px;overflow:hidden}` + `.n-track{transform: translateY(-idx*22px)}`，`setInterval(nextNotice, 5000)`，`onBeforeUnmount` 清表。
- `quickOn` 用 `router.currentRoute.value.path` 判断当前高亮哪一段（含 `startsWith(path + '/')`）。

**交互要点**：

- 公告整条 `@click="openNotice"` → `push('/notice/' + notices[idx].id)`；右侧「换一条」要 `@click.stop`，否则冒泡触发跳转。

- `go(t)` 支持 `t.external`（`window.open(url,'_blank','noopener')`）/ `t.internal` / 默认 `/tool/:id`——当前 `tools.js` 里没有任何工具带这两个字段，**这三个分支是给未来扩展留的**。
- 行末的 `defineExpose({ openLogin })` 是**残留代码**（`router-view` 默认插槽没传 ref，实际不会被调）。

- 「看全部分类 ›」→ `pickAll()`：`ui.setCat('all')` 把顶部「工具」下拉切回全部，再 `router.push('/tools')` 去全量页。（**修过的 bug**：这里原本是 `push('/')`，等于把用户留在首页、什么都没变，看起来像「点了没反应」。判断这类 bug 的直接办法：`pickAll` 的目标锚点就是 `/tools`，全量页的分类 pill 才是「全部分类」真正的展示位。）

### 6.2 工具全量页 `Tools.vue`（`/tools`）

**做什么**：全 22 个工具的九宫格 + 分类 pill + 搜索框。

**技术**：`el-input`/`el-icon`/`el-empty`、`tools`+`categories` 配置、`useUiStore`。

**关键实现**：

- `kw`/`curCat` 都是 store 的**双向 computed**（`get:()=>ui.keyword, set:v=>ui.setKeyword(v)`）——历史 bug 是「把传入值抄进本地 ref 只认一次，停在 /tools 时改顶部框就没反应」。
- 调色改成本地**按 id 哈希**（`h = (h*31 + charCodeAt) >>> 0`），「乱一点但固定，刷新不变」。
- 分类 pill 数据源就是 `categories[0]`（全部工具），**不再重复加一个「全部」**。

- 窄屏分类条改**单行横向滚动**（`flex-wrap:nowrap; overflow-x:auto` + 隐藏滚动条 + `-webkit-overflow-scrolling:touch`），「不再折成两行占半屏」。
- pill 的选中态 `.cat.on` 是 `background: var(--tb-primary)` + `color:#fff`，**不随 --tb-pill 变**——这是有意为之：选中态必须一直是实心高对比，不能跟着表面色一起暗下去。

### 6.5 登录 / 注册 `Auth.vue`（`/auth`）

**做什么**：整屏独立登录页（不套主站外壳），两档面板 —— `quick`（主角：本机号一键登录，可在本页改号）+ `reset`（手机号 + 验证码 + 新密码，一步找回密码）。

**技术**：`<style lang="less" module>`、`el-input/el-button/el-link/el-icon`、三个 store、`SmsFields.vue`、ui.module.less 共享类。

**关键实现**：

- 一个句柄拿两类样式：`const s = { ...shared, ...useCssModule() }`。
- `mode` 初值 = `route.query.mode==='reset' || ui.authMode==='reset' ? 'reset':'quick'`；`setMode` 顺手写 `ui.authMode`。
- **一键登录主链路**：`onMounted` 里 `setTimeout(700ms)` 把 `phone` 填成 `DEMO_PHONE='13800138000'`（注释：演示环境模拟取本机号码，真机这里是运营商号码认证服务回调），期间 shimmer 骨架；`maskPhone` 判 `/^1[3-9]\d{9}$/` 后显示 `138****8000`。
- **本页改号**：`startEdit()` 把号码搬到 `lg.phone`、`lg.code=''`；`useDevicePhone()` 还原；`canSubmit` 判断「本机号没动 → 免验证码，改过号 → 必须验码」。
- **演示验证码**：`rollCode()` 用 `Math.floor(1000 + random*9000)` 生 4 位存 `demo[which]`，页面明写「演示环境不发短信：本次验证码为 XXXX」；倒计时 `cd.login/cd.reset` 共用一个 `setInterval`，「两个面板都归零就停表」。
- **密码强度** 3 分制（≥6 位 +1、含字母且含数字 +1、≥10 位或含非字母数字 +1），`levelLabel = ['','一般','不错','很强']`，三段进度条按 level 上色。
- **后端没接上时的兜底**：`doQuick/doSmsLogin/doReset` 的 catch 里先按正则判断是否为业务错误（`/手机号|格式/`、`/验证码|手机号|不存在|格式/`），不匹配则 `user.setSession('demo-'+Date.now(), '同学'+phone.slice(-4), 'demo-'+random)` + 「已用演示账号登录（P2 接后端后走真实接口）」。
- `redirect()` 只认 `route.query.redirect` 且必须以 `/` 开头（防开放重定向）；`goBack()` 看 `window.history.state?.back` 决定 `router.back()` 还是跳 redirect。
- 组件里 `theme.apply()` 在 **setup 顶层直接调用**（不在 onMounted），因为 `/auth` 在 AppLayout 之外。

**交互要点**：协议勾选自己画圆点（不用 `el-checkbox`，「那颗方块在圆角面板里很跳」），`agreed` **默认 true**（「别让人为了登录先读两千字」）；第三方登录（微信/QQ/邮箱）只做 44px 圆形占位，点击 `ElMessage.info(...+'登录暂未接入')` —— **TODO**；暗色用 `:global(html.dark) .glass{}`；1000px 时 `.stage` 单列且 `.intro{display:none}`（手机端别把表单挤没了），520px 整体再收一档。

**`components/SmsFields.vue`**：手机号 + 验证码这对输入组的受控复用组件（寻回密码面板共用）。`props {phone, code, countdown, tip}`，`emits ['update:phone','update:code','send','submit','auto']`；输入过滤 `String(v).replace(/\D/g,'').slice(0, 11/6)`（「输入法带出来的空格/连字符会让人以为验证码填错了」）；`phoneOk` 格式不对时**只把提示文字标红**（「别整块变色，否则提示行会把下面内容顶得忽上忽下」）。`.codeBtn { composes: tb-btn from global }`，`.codeRow > :global(.el-input){flex:1}` + `:global(.el-input__wrapper){min-height:@h-input}`——「自己画的按钮，高度必须跟输入框一致，差几像素整行就歪」；`.m-xs`（620px）时 `.lbRow` 改竖排。

**内联发帖面板（本次改动过）**：

- 面板 `v-if="postOpen"` 插在帖子列表**上方**（不是弹窗，注释：「功能表单一律就地填，用户不该被盖住视线」）。
- **本次新增滚动定位**——页面一长时面板在首屏外，用户只会看到列表往下顶一下，以为按钮没反应：

```js
const composerRef = ref(null);

// 内联面板是插在帖子列表上方的，页面一长它就在首屏外 —— 展开后把它滚进视野
async function openPost() {
  postOpen.value = !postOpen.value;
  if (!postOpen.value) return;
  await nextTick();

  composerRef.value?.scrollIntoView({ behavior: 'smooth', block: 'center' });
}
```

**做什么**：资金概览（可用余额 + 充值/提现，托管中金额由本地订单实时算）+ 提现面板（页内展开）+ 四个平级分区：交易流水 / 收款账户 / 支付方式 / 我的卡（含绑卡，绑定表单页内展开）。从「我的」页收付款卡片带 `#flow` 进来直接滚到流水。

- 四个 `el-tab-pane`：`flow`（默认）/ `receive` / `pay` / `cards`，`tab = ref('flow')`。
- `scrollToFlow()` 里**先 `tab.value = 'flow'` 再滚** —— 否则用户停在别的页签上时，滚过去不是这块。
- 样式只调 `:deep(.el-tabs__header)` 的下边距和 `:deep(.el-tabs__nav-wrap::after)` 的线色（EP 默认那条偏灰，与卡片分隔线不是一个色）。**页签配色不用写**，自动吃主题 store 写的 `--el-color-primary`；手机端（`max-width:900px`）把 `:deep(.el-tabs__item)` 的左右 padding 收到 10px、字号 13px，四个页签才排得下 390px。

**流水默认只露 6 条（2026-10-11 改）**：流水 = 钱包 ledger + 订单派生，攒多了能有几十条，全量平铺会把面板撑得很长。`FLOW_PREVIEW = 6` + `flowExpanded` ref，`flowShown` computed 决定渲染 `flow` 还是 `flow.slice(0, FLOW_PREVIEW)`；底部 `.moreBtn` 一行切换（`v-if="flow.length > FLOW_PREVIEW"`），文案「展开全部 N 条 / 收起流水」+ 旋转 chevron（`.chev` 转 90° 朝下、`.chevUp` 转 -90° 朝上）。

- 展开态**切页签后不重置**（`flowExpanded` 是页面级 ref），回到流水页签仍是展开的 —— 有意保留用户刚才的浏览状态。
- 底部固定 tabbar 不会压住展开按钮：390×844 滚到底实测，按钮底边距导航栏顶边还有 **19px** 留白。

- **下载**：`URL.createObjectURL(blob)` + `<a :download>`——**没有 FileSaver.js**。

### 7.1 文本 / 编码类（text）

#### JSON 格式化 `JsonFormat.vue`

- **功能**：粘贴 JSON → 输出缩进 2 空格的美化版，或压成一行的紧凑版，兼做合法性校验。
- **技术**：**纯 `JSON.parse` / `JSON.stringify`**，无第三方库；`el-input type="textarea"` + 4 个按钮。
- **实现**：格式化 `JSON.stringify(JSON.parse(input), null, 2)`；压缩 `JSON.stringify(JSON.parse(input))`。三个操作（格式化 / 压缩 / 校验）各自 `try/catch`，把 `e.message` 拼进 `msg` 显示在操作栏右侧（`msgType` 为 ok 绿 / err 红）；输出框 `readonly`。
- **边界**：空输入走 `JSON.parse('')` 抛错 → 被 catch 成「解析失败」，有兜底但不算友好。
- **交互**：非实时（点按钮才跑）；无示例值、无历史、无复制按钮（需手选）。

#### 时间戳转换 `Timestamp.vue`

- **功能**：双向转换——时间戳（秒/毫秒）→ 可读日期；日期选择器 → 同时给出秒和毫秒。
- **技术**：原生 `Date` + `Number()` + `String().length` 判位；`el-card/el-input/el-date-picker type="datetime" value-format="YYYY-MM-DD HH:mm:ss"`。
- **实现**：`new Date(n).toLocaleString('zh-CN')`；**毫秒→秒靠位数猜**：`if (String(n).length === 10) n *= 1000`（依赖输入是纯数字）。反向转换时把 `-` 全替换成 `/`（`pick.replace(/-/g,'/')`）——这是 iOS/Safari 上 `new Date('2026-10-01 00:00:00')` 会 Invalid Date 的经典兜底。
- **边界**：`if (!n)` 挡空串和 0；`isNaN(d.getTime())` 挡「无效时间戳」。
- **布局**：`.row{display:flex}` + `:deep(.el-input){flex:1;min-width:0}`（`min-width:0` 是防长 placeholder 把按钮挤出行的关键）。

#### Base64 编解码 `Base64.vue`

- **功能**：文本 ↔ Base64 互转（**重点解决中文 Base64 乱码**）。
- **技术**：`btoa/atob` + `encodeURIComponent/decodeURIComponent` + `escape/unescape` 做 UTF-8 桥接；无第三方库（**没用 `he`**）。
- **实现**：编码 `btoa(unescape(encodeURIComponent(v)))`；解码 `decodeURIComponent(escape(atob(v)))`。`escape/unescape` 虽已废弃但仍有效，是这套写法能正确处理中文/emoji 的核心。
- **边界**：解码 `try/catch` → `ElMessage.error('解码失败，不是合法 Base64')`；编码超长会抛 `InvalidCharacterError` 但当前**未 catch**（真实隐患）；空输入产出空串。
- **交互**：上下两个 textarea（下只读）+ 编码/解码按钮，**点击触发**；无示例、无历史。

#### 哈希计算 `Hash.vue`

- **功能**：对文本算 MD5 / SHA-1 / SHA256，输出 hex + 字符数。
- **技术**：**Web Crypto `crypto.subtle.digest`**（SHA 系列）+ **手写的标准 MD5（RFC 1321）**；`TextEncoder` / `DataView` / `Int32Array` / `Uint8Array`。
- **实现**：
  - MD5 手写：预计算正弦表 `SIN_K = Array.from({length:64},(_,i)=>Math.floor(Math.abs(Math.sin(i+1))*4294967296))` 与 64 项轮转表 `SHIFT`；`TextEncoder` 转字节；填充 `total = ((((len+8)>>6)+1)<<6)` 对齐 64 字节块，`buf[len]=0x80` 打标志，尾部小端写长度；四轮非线性函数 `(bb&cc)|(~bb&dd)` / `(dd&bb)|(~dd&cc)` / `bb^cc^dd` / `cc^(bb|~dd)`，配 `(f<<SHIFT[j])|(f>>>(32-SHIFT[j]))` 循环左移；输出 `setInt32` 后 `padStart(2,'0')` 转 hex。
  - SHA-1/256 直接 `crypto.subtle.digest('SHA-1'|'SHA-256', new TextEncoder().encode(v))`，`busy` 控 loading。
- **边界**：空文本提示「请输入文本」；`calc()` 外层 `try/catch/finally` 保证 busy 复位。注释写明「Web Crypto 只提供 SHA-1/256/384/512，没有 MD5，所以自己实现一份」；MD5 在主线程跑，大文本会卡顿。
- **复制**：`navigator.clipboard?.writeText(v)`。

#### 进制转换 `Radix.vue`

- **功能**：输入某进制数字，一次性输出 2 / 8 / 10 / 16 / 36 五种表示，高亮目标进制。
- **技术**：**`BigInt`**（避免大整数丢精度）+ 动态 `RegExp` + `String.prototype.toString(base)`。
- **实现**：十进制走 `BigInt(s)`（先 `/^[+-]?\d+$/` 校验）；非十进制**手工竖式累加** `n = n*BigInt(from) + BigInt(parseInt(ch, from))`；输入先 `replace(/[_,\s]/g,'')` 容忍下划线/逗号/空格分隔。
- **边界**：非十进制用 `new RegExp(\`^[0-9a-fA-F]{1,${from}}$\`)` 动态卡位数；解析失败 `el-alert type="error"`；二进制输出 4 位分组补零并 `replace(/(.{4})(?=.)/g,'$1 ')` 插空格；负数输出带 `-`（取绝对值再加号）。

#### 正则测试 `Regex.vue`

- **功能**：输入正则 + flags + 目标文本，列出全部匹配、位置、捕获组。
- **技术**：原生 `new RegExp()` + `exec` 循环 + `m.slice(1)` 取捕获组；`el-input/el-table/el-alert`。
- **实现**：
  - 合法性靠「构造是否抛错」：`valid = computed(() => { try { new RegExp(pattern, flags); return true } catch(e){ err.value = e.message; return false } })`；「匹配」按钮 `:disabled="!valid"`。
  - 执行时 `const f = flags.value.replace(/[gy]/g,'') + 'g'` —— **强制补 `g` 才能循环找全部**，同时剔掉用户传的 y/g 避免冲突。
  - 死循环兜底：`if (m[0]==='') re.lastIndex++;`（零宽匹配如 `a*`）+ **500 条上限截断**。

#### JWT 解析 `Jwt.vue`

- **功能**：粘贴 JWT，把 header / payload 还原成 JSON 展示，signature 原样显示，算过期状态。
- **技术**：**base64url 手写解码**（`-`→`+`、`_`→`/`、补 `=`）+ `atob` + `escape/decodeURIComponent` + `JSON.parse`；`computed` 派生过期信息。
- **实现**：`b64url(str)` 内 `str.replace(/-/g,'+').replace(/_/g,'/')` 后 `atob(b + '==='.slice((b.length+3)%4))`——用 `'==='.slice(...)` 这个巧劲把长度补到 4 的倍数；外层 `decodeURIComponent(escape(...))` 保中文 claim 不乱码。
- **边界**：`parts.length !== 3` 提示「JWT 必须是由两个点分隔的三段」；解析段 try/catch。页面底部刻意加提示：**前端只能解析目视核对，验签必须服务端做**（本地拿不到密钥也算不了 HMAC）——**不提供验签功能**。
- **交互**：`expInfo` computed 算 `exp*1000 - Date.now()`，过期显示红色「已于 … 过期」，未过期显示「剩余 N 天 M 小时」；760px 以下双栏塌成一栏。

### 7.2 图片处理类（image）—— 全走浏览器 Canvas，零后端

#### 图片压缩 `ImageCompress.vue`

- **功能**：选图 → 定 JPEG 质量 + 最长边 → canvas 重绘导出 JPEG，对比原图/压缩后体积与节省率。
- **技术**：`el-upload :auto-upload="false" :show-file-list="false" accept="image/*"` → `file.raw`；`URL.createObjectURL`；`new Image()` + `onload/onerror` Promise 化；`document.createElement('canvas')` + `2d.drawImage()` + **`canvas.toBlob(cb,'image/jpeg',q)`**；`naturalWidth/naturalHeight`；`Blob.size`。
- **实现**：`loadImg(file)` 自己封装 Promise 包 `onload/resolve` 与 `onerror/reject`；**等比缩放** `k = maxSide / Math.max(w,h)`，`maxSide=0` 表示不缩放；`sizeText()` 自己实现 B/KB/MB 三级格式化；节省比 `Math.max(0, Math.round((1 - blob.size/srcSize)*100))` 防负数。
- **下载**：`<a :href="out" :download="fileName">`（Blob URL + 原生 a[download]），文件名原名去扩展名 + `-compressed`。
- **边界**：`if (!rawFile) return`；`busy` + `finally`；**没有对超大图（canvas 上限约 16384px）做显式限制**。已知小隐患：`onPick` 里 `loadImg` 未 catch；`run()` 重新 `createObjectURL` 而非复用旧 URL（objectURL 泄漏，未 `revokeObjectURL`）。

#### 格式转换 `ImageConvert.vue`

- **功能**：PNG / JPEG / WebP 互转，输出体积变化百分比。
- **技术**：同上的 Canvas 链路，多一步 `ctx.fillStyle + fillRect` 铺白底。
- **实现**：`canvas.toBlob(res, fmt, fmt==='image/png' ? undefined : quality/100)`——**PNG 走无损、不传 quality**；`if (fmt==='image/jpeg') { ctx.fillStyle='#ffffff'; ctx.fillRect(0,0,w,h) }`（「JPEG 不支持透明，先铺白底，否则透明区会变黑」）；`delta` computed 算 `Math.round((1-out/src)*100)`，正负分别显示「省 N%」/「大 N%」；`extOf(mime)` 映射扩展名，兜底 `.png`。
- **交互**：画质 slider **仅非 PNG 时显示**（PNG 时提示「PNG 不支持画质参数，恒为无损」）。

#### 图片水印 `ImageWatermark.vue`

- **功能**：给图片加**文字**水印（9 宫格定位、字号、透明度、颜色、描边），输出 PNG。
- **技术**：Canvas 2D 全套 `ctx.font / textBaseline / globalAlpha / textAlign / strokeText / fillStyle / fillText` + `el-color-picker / el-radio-group / el-switch` + `canvas.toBlob(res,'image/png')`（保留 alpha）。
- **实现**：
  - 九宫格 `POS = ['tl','tc','tr','ml','mc','mr','bl','bc','br']`；`pad = Math.round(canvas.width*0.04)+8` 留 4% 边距；`ctx.font = \`600 ${size}px system-ui, -apple-system, "PingFang SC", sans-serif\``（中文栈）；
  - `textAlign` 按 `pos[1]`（l/c/r）取 left/center/right，`x` 相应取 `pad / width/2 / width-pad`，`y` 同理；
  - **描边**：`strokeStyle='rgba(0,0,0,.45)'`、`lineWidth = Math.max(2, Math.round(size/12))`，先 `strokeText` 再 `fillText`（暗底更清晰）；
  - `globalAlpha = opacity/100`，画完**必须复位为 1**（代码里做了）。
- **边界**：文字 `maxlength=60`；`if (!rawFile) return`；`busy` + `finally`；文件名原名 + `-wm`。

### 7.3 文档类（doc）—— pdf-lib 懒加载

#### PDF 合并 `PdfMerge.vue`

- **功能**：多份 PDF 按列表顺序合并成一份，可上移/下移/移除。
- **技术**：`pdf-lib`（**动态 `await import('pdf-lib')`**，注释「别进主包」）+ `el-upload multiple` + Blob。
- **实现**：
```js
const { PDFDocument } = await import('pdf-lib');
const merged = await PDFDocument.create();
for (const f of files.value) {
  const src = await PDFDocument.load(await f.raw.arrayBuffer());
  const pages = await merged.copyPages(src, src.getPageIndices());
  pages.forEach(p => merged.addPage(p));
}
const bytes = await merged.save();
```
- **边界**：`onPick` 里 `file.raw.type === 'application/pdf'` 过滤，否则 warning「只能选择 PDF 文件」；`mv(i,d)` 解构交换实现上移/下移，首项「上移」、末项「下移」disabled；失败 `ElMessage.error('合并失败：'+e.message)`。
- **下载**：`URL.createObjectURL(new Blob([bytes],{type:'application/pdf'}))` → `<a :download>`，文件名 `merged-Nfiles.pdf`（用 `File.arrayBuffer()`，**无 FileReader**）。

#### PDF 拆分 `PdfSplit.vue`

- **功能**：先显示总页数，再按「页范围提取」（`1-3,5,7-9`）或「逐页拆分」两种模式导出。
- **技术**：同 pdf-lib 链路 + **`Set` 去重 + 排序 + 0 基索引映射**的页范围解析 + `el-radio-group` 双模式。
- **实现**：
```js
// "1-3,5,7-9" → [0,1,2,4,6,7,8]（转 0 基）
const out = new Set();
for (const part of String(s).split(/[,\s]+/).filter(Boolean)) {
  const [a, b] = part.split('-').map(x => parseInt(x, 10));
  if (Number.isNaN(a)) continue;
  const end = Number.isNaN(b) ? a : b;
  for (let i = Math.max(1, a); i <= Math.min(max, end); i++) out.add(i);
}
return [...out].sort((x, y) => x - y).map(n => n - 1);
```
  `split(/[,\s]+/)` 兼容空格分隔，`Math.max(1,a)` / `Math.min(max,end)` 双向夹取防越界，Set 自动去重。
- **性能**：`const srcPdfBytes = await srcDoc.save();` **留底一份字节**，两种模式都从 `PDFDocument.load(srcPdfBytes)` 重建（「避免多次 save 反复解码」）；逐页拆分时循环 `copyPages(doc,[i])`，文件名 `page-01.pdf` 用 `padStart(2,'0')` 补零。
- **下载**：每个结果项 `<el-button link :href="r.url" :download="r.name">下载</el-button>`。已知未 revoke 旧 URL（逐页拆 100 页会留 100 个 Blob）。

### 7.4 实用工具类（util）

#### 密码生成 `Password.vue`

- **功能**：按勾选字符池生成随机强密码 + 强度等级 + 理论熵 bits。
- **技术**：**`crypto.getRandomValues(new Uint8Array(n))`**（注释：「crypto.getRandomValues 是密码学安全的，Math.random 不能用来生成密码」）+ `Math.log2(new Set(pool).size)` 算熵；`el-checkbox / el-input-number / el-input readonly`。
- **实现**：
  - 取随机 `const out = new Uint8Array(len); crypto.getRandomValues(out); s += pool[out[i] % pool.length]`；
  - **「每类至少出现一个」保底**：`strict.length > 1` 时对每类单独 `crypto.getRandomValues(new Uint8Array(1))` 取一个字符，再替换到指定位置（「否则弱配置会产出一串纯 a-z」）；
  - 排除易混字符 `pool.replace(/[0O1lI]/g,'')`；
  - 熵 `bits = len * Math.log2(pool.size)`，`level = bits>=80?'strong': bits>=60?'mid':'weak'`，对应「很强/中等/偏弱」三色 + 4px 进度条。
- **边界**：`len` 由 `el-input-number :min=6 :max=64` 卡死；`!use.length` 置空串；`copy()` 空值兜底。
- **已知问题**：`pool[out[i] % pool.length]` 的**取模有偏（modulo bias）**，pool 大小非 256 约数时各字符概率不等（未做拒绝采样）；「每类保底」是替换已生成字符，极端下不保证每类至少一个。
- **复制**：`navigator.clipboard?.writeText(pwd.value)`。

#### UUID 生成 `Uuid.vue`

- **功能**：批量生成 1–200 个 UUID v4，单条复制或整批复制。
- **技术**：**`crypto.randomUUID()`** + 手写 v4 兜底。
- **实现（注释写得很清楚）**：「`crypto.randomUUID` 只在安全上下文（https / localhost）可用，局域网 http 访问会没有，所以留一条手写兜底」：
```js
if (crypto.randomUUID) return crypto.randomUUID();
const b = new Uint8Array(16); crypto.getRandomValues(b);
b[6] = (b[6] & 0x0f) | 0x40;   // version 4
b[8] = (b[8] & 0x3f) | 0x80;   // variant 10x
const h = Array.from(b, x => x.toString(16).padStart(2,'0')).join('');
return `${h.slice(0,8)}-${h.slice(8,12)}-${h.slice(12,16)}-${h.slice(16,20)}-${h.slice(20)}`;
```
- **交互**：`count` 由 `el-input-number :min=1 :max=200` 限制；`copyAll` 用 `join('\n')` 换行分隔并提示「已复制 N 条」；结果区 `max-height:380` 内部滚动。

#### 颜色转换 `Color.vue`

- **功能**：输入 HEX / RGB / HSL 任一 → 同时输出 HEX / RGB / HSL / HSV / CMYK 五种，可实时联动。
- **技术**：三条解析正则 + **HSL↔RGB 互转公式** + CMYK 公式 + `computed` 派生 + `watch` 报错 + `el-color-picker :predefine`。
- **实现**：正则 `/^#?([0-9a-f]{3}|[0-9a-f]{6})$/i`（3 位自动 `split('').map(x=>x+x).join('')` 展开）、`/rgba?\(…\)/i`、`/hsla?\(…\)/i`；`toHsl` 标准 `l=(max+min)/2`、`s = l>0.5 ? d/(2-max-min) : d/(max+min)`；`fromHsl` 归一化 `h=((h%360)+360)%360`；**CMYK**：`k = 255 - Math.max(r,g,b)`，`k===255` 直接返回 `[0,0,0,100]`（除零兜底）。
- **边界**：`watch(raw)` 在**输入为空时不报错**（`err = !raw.value ? '' : …`），只有非空且解析不出才警示。
- **交互**：**完全实时**（`c = computed(() => parse(raw.value))`），左侧 30px 色块预览 + 下方 5 个预设色按钮；每行带「复制」。

#### 单位换算 `Unit.vue`

- **功能**：长度 / 重量 / 面积 / 体积 / 温度五类互转，附常用参考表。
- **技术**：常量表 `GROUPS` + `FACTOR` 因子表 +「先归一到基准单位再反算」+ `el-tabs / el-select / el-alert`。
- **实现**：`toBase(v,u)` / `fromBase(b,u)` 双函数；非温度走 `v*FACTOR[u]` / `b/FACTOR[u]`（长度基 m、重量基 kg、面积基 m²、体积基 L）；**温度走线性公式** `F=(v-32)*5/9`、`K=v-273.15`，反向 `b*9/5+32`、`b+273.15`。FACTOR 收录 `in:0.0254, ft:0.3048, yd:0.9144, mile:1609.344`、`lb:0.45359237, oz:0.028349523, jin:0.5`、`acre:4046.8564224`、`gal:3.785411784, cup:0.24`、`mL_CN:1e-3`。
- **精度**：「温度最低精度 0.01，其余 6 位有效数字」→ `Number(r.toFixed(cat==='temp'?4:6)).toString()`；极小值走科学计数法；`val` 空或 NaN 提示「请输入有效数值」；`from===to` 原样返回。
- **坑处理**：`watch(cat, …)` 把 from/to 落到新分类单位（「否则会从长度切到温度还带着 'cm' → 报错」）；`conv()` 在 script 末尾**直接调一次**（首次进页面就给结果）。

**Model（2 个）**：

- `models/User.js` → 集合 `users`：`username`(required,unique)、`password`(`select:false`，默认不查出密码)、`nickname`、`avatar`；`timestamps:true`。**没有 `phone` 字段**。
- `models/History.js` → 集合 `histories`：`user`(ObjectId ref User, index)、`toolId`(index)、`toolName`、`summary`；`timestamps:true`。

**完整路由（8 条）**：

| 方法 | 路径 | 作用 | 鉴权 |
|---|---|---|---|
| GET | `/api/health` | 健康检查 `{db:'mongo', time}` | 公开 |
| POST | `/api/user/register` | 非空 + 密码≥6 + 存在性查重；bcrypt 10 | 公开 |
| POST | `/api/user/login` | **必须 `.select('+password')`** 才能 `compareSync`；签发 token 7d | 公开 |
| GET | `/api/user/me` | `findById(...).select('-password')` | 需 auth |
| POST | `/api/tool/history` | 记录一次工具使用 | 需 auth |
| GET | `/api/tool/history` | 分页历史（`sort(createdAt:-1)`） | 需 auth |
| GET | `/api/tool/rank` | 排行 Top10（aggregation `$group → $sort → $limit → $project`） | 公开 |
| POST | `/api/upload/image` | 图片处理骨架（同 MySQL 版） | 需 auth |
| POST | `/api/upload/pdf` | 骨架，直接 fail | 需 auth |

**关键差异（重要）**：

1. **Mongo 连不上 = 整个服务起不来**——`connect()` 的 catch 里 `process.exit(1)`，且 `app.listen` 写在 `connect().then()` 里。对比 MySQL 版「DB 挂了服务照常监听」。
2. **比 MySQL 版少 4 条接口**：没有 `/api/user/avatar`、`/sms-login`、`/quick-login`、`/reset-password`——**Mongo 版只支持用户名+密码登录，没有手机号体系**；`avatar` 字段留着但没有任何接口能写它。
3. `password: {select:false}` 的坑：别处直接 `findOne({username})` 取不到密码，登录漏写 `.select('+password')` 就是「用户永远不存在」。
4. `db/mongo.js` 用 `serverSelectionTimeoutMS: 5000`；`db` 字段区分两版健康检查。
5. 两版若共用同一把 `JWT_SECRET`，切换数据库后旧 token 的 userId 语义不同会串号。

### 9.3 两版对照

- **都有的 8 条**：register / login / me / tool history(POST+GET) / tool rank / upload image / upload pdf，外加 `/api/health`。
- **只有 MySQL 版有的 4 条**：`avatar` / `sms-login` / `quick-login` / `reset-password`。
- **两版都没有的**：任何 item / 闲置商品接口（`POST /api/items` 等）——这正是 `Publish.vue` 那行 TODO 要补的空位；社区帖子、订单、消息、收藏、评价也一条都没有。

### 10.1 `client/scripts/serve.mjs`（单端口服务）

发布用的是它，不是 nginx / Vite dev：

- **子应用同源**：`dist/idx/`（由 idle-market 构建产物 `cp -r` 进来）挂在 `/idle-app/` 下。
- **`/api/*` 占位**：统一回 `501 application/json`「接口待接入云服务」——分明告诉前端"这里还没接"，比静默 404 好排查。
- 目录解析按**脚本自身位置**定位，这样从任何 cwd 都能起，云端也稳。

云端 startCmd（端口必须带默认值，`$PORT` 在云端 shell 里是**空字符串**）：

```

npm --prefix client run build &&
npm --prefix idle-market install --no-audit --no-fund &&
npm --prefix idle-market run build &&
cp -r idle-market/dist client/dist/idx &&
PORT=${PORT:-3000} node client/scripts/serve.mjs
```

**为什么发的是仓库根目录而不是 `client/`**：闲置市场源码不在 `client/` 里，要一起上传，构建阶段合并进 `dist/idx`；根目录没有 package.json，依赖在子包里，所以用 `npm --prefix` 分别装。

### 10.4 浏览器视觉自验（本机可行，2026-10-04 实测通）

**结论先说：本机能真实渲染自验，不需要额外装浏览器。** 之前判断「拉不到 Chromium」是找错地方了 —— 没往 360 极速浏览器里找。

| 项 | 值 |
|---|---|
| 可执行文件 | `D:\360ChromeX\Chrome\Application\360ChromeX.exe`（2.2MB 壳） |
| 内核 | Chromium **132.0.6805.0**（`--remote-debugging-port` 报 `Chrome/132.0.6805.0`，UA 带 `QIHU 360EE`） |
| 进程名 | `360ChromeX.exe`；user-data 在 `%LOCALAPPDATA%\360ChromeX`、`D:\360ChromeX\Chrome\User Data` |
| 方案 | **CDP（Chrome DevTools Protocol）驱动** —— 与 Playwright/Puppeteer 同源协议，不需要下载任何浏览器 |

**为什么不用 WorkBuddy 自带的预览面板**：它的应用预览看的是**客户端自己托管的运行时**，跟我们发布到 `*.app.workbuddy.host` 的这份静态产物不是同一个实例，验证不到线上的东西。`agent-browser` 那条路是「下载独立 Chromium」，被外网（googlechromelabs.github.io）挡了 —— 而**复用已有的 360 内核一步都不用下载**。

#### 操作步骤

```bash
# 1) 后台常驻启动带调试端口的浏览器（headless，不弹窗、不影响你正常用浏览器）
"/d/360ChromeX/Chrome/Application/360ChromeX.exe" --headless=new --disable-gpu --no-sandbox \
  --hide-scrollbars --remote-debugging-port=9333 \
  --user-data-dir=%LOCALAPPDATA%/Temp/crcdp/profile --window-size=1280,900 about:blank

# 2) 截图（node cdp.js <输出png> <url> [--w 390] [--h 844] [--theme dark] [--js "..."]）
node cdp.js v-tools-dark.png "https://campus-toolbox-20868.app.workbuddy.host/tools" --w 390 --h 844 --theme dark

# 3) 量化诊断（node verify.js <url> dark <诊断js> --w 390 --h 844）
node verify.js "https://.../me" dark diag-me.js --w 390 --h 844
```

助手侧用的三个脚本（`cdp.js` 截图 / `verify.js` 量化诊断 / `diag-*.js` 诊断表达式）在 `F:\WorkBuddy\2026-10-04-08-56-44\`。

#### 四个坑（照抄别踩）

1. **Node 的 `spawnSync` 启动这个 exe 报 `EBUSY`**（沙箱也挡），**改用 shell 直接起**就正常。所以「启动浏览器」那一步走 Bash，脚本只负责连 CDP。
2. **`/json/new` 只接受 `PUT`**（`GET` 会被拒 + 提示 `Using unsafe HTTP verb GET`）；且最好**复用已有的 `type:"page"` target**，避免每次新建。
3. **复用 target 时必须显式 `Page.navigate`**，否则截到的是 `about:blank`（表现为 2.8KB 白图）。
4. **深色模式要加的是 `class="dark"` 不是 `data-theme="dark"`** —— `stores/theme.js:37` 是 `root.classList.toggle('dark', this.dark)`，选择器写的 `html.dark`。只改属性 → 深色完全不生效。

另外：CDP 里 `Emulation.setDeviceMetricsOverride` 才能压到 390 窄屏；默认 1280 拿到的是**桌面布局**，跟手机截图不是一回事（本次就靠它发现了「头像居中在桌面/移动端都要验」这点）。**只往 `html` 上 `classList.add('dark')` 验不到组件层状态**（theme store 的按钮高亮仍停在原处），要验最终态得用 `--js` 真点「深色」那个按钮。

#### 本次实测结论

| 改动 | 自验方式 | 结果 |
|---|---|---|
| 深色 tab 栏 | 计算样式 + 像素截图 | 未选中 pill 底色 `rgba(255,255,255,.09)` 压在 `rgb(23,27,46,.55)` 上，与 `--tb-sub` 文字实色对比度 ≈5.6（>WCAG AA 4.5）；截图清晰可辨 |
| Me 头像居中 | 390 窄屏量 `getBoundingClientRect` | `centerX 195 == parentCenterX 195`、`margin-left/right = 141px` → 真居中（桌面 1280 下同样相等） |
| 发帖滚动定位 | CDP 真点「+ 发帖」 | 点击后 `composer` `top=222 h=400`、视口 844 → 完全在视口内，`scrollY 0→462` 确实滚了 |
